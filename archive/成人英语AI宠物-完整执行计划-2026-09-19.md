# 1. 项目目标



| 项目    | 当前定义                                    |
| ----- | --------------------------------------- |
| 产品定位  | 一只记得用户、通过认知与语言成长驱动用户自然学习英语，并与用户经历完整人生阶段的互动宠物 |
| 目标人群  | 大众成人英语学习者，优先适合 “有一定基础、想提高口语但缺少使用环境” 的人  |
| 核心价值  | 用户感受到陪伴、故事和共同成长；系统执行严谨学习计划，以理解、造句、间隔复现和跨场景迁移确保真实掌握，而不依赖打卡、金币、考试羞耻和宠物惩罚 |

# 2. 产品范围锁

开发过程中优先保证以下闭环：



```
宠物发生一件事

   ↓

用户听懂并用英语回应

   ↓

表达影响宠物反应或事件结果

   ↓

系统记录用户的语言与共同经历

   ↓

旧表达和旧事件在未来自然出现
```

### P0 必须完成



* 一只固定 AI 宠物；

* 成人化、稳定的宠物人格；

* 每日生活事件；

* 文字输入；

* 宠物英文语音；

* 所有功能界面统一使用中文；英文只作为学习内容出现，并配人工中文译文；

* 用户按住说话与语音转写；

* 对话后的轻量英语反馈；

* 生活、语言和关系三类长期记忆；

* 共同记忆册；

* 旧表达在新情境中的自然复现；

* 用户查看、修改、删除和暂停记忆；

* 离开后可自然返回，不惩罚断签；

* 固定、人工编写且版本化的对话与事件内容库；

* 预设意图与关键词匹配，只进入声明过的固定回复和事件分支；

* 无法可靠匹配时使用中文安全兜底，不伪装成开放式理解；

* Morrow 从出生、童年、上学、校园成长、毕业到步入社会的长期成长主线；

* Morrow 的认知与语言能力随章节逐步成长：出生期只会少量词和极短句，后续逐章增加词汇、搭配、句型和表达能力；

* 首次使用进行约 3 分钟的轻量英语水平测试，只决定用户在同一故事事件中的提示量和表达挑战，不跳章节；

* 同一事件按用户水平提供不同任务：基础用户认词和短句，中等用户完整造句，进阶用户解释、改写、比较或用简单英语说明复杂意思；

* 建立词汇、搭配和句型的掌握状态，只有经过独立理解、独立表达、间隔复现和跨场景迁移后才标记为稳定掌握；

* 用户未掌握的内容不阻塞剧情，但必须在后续合适场景中自然再次出现；

* 学习辅助逐渐退出：从中文、图片、选项和参考句，逐步减少到关键词，最终要求独立表达；用户随时可以重新开启帮助且不受惩罚；

* 幼年 Morrow 通过指向、观察、试错、提问和生活任务认识世界，用户通过命名、描述、纠正、执行和表达偏好帮助它学习；

* 所有主要英文学习内容配套人工中文译文；

* 英文内容区域右下角提供“查看中文 / 收起中文”，默认收起；

* 小程序与 App 共用统一后端、数据库、固定内容、事件、记忆和语音服务。






### 首版明确不做



* 多宠物抽卡和稀有度系统；

* 大型家园装修；

* 好友、排行榜和 PK；

* 完整语法课程；

* 考试题库和教材同步；

* 实时电话式连续语音；

* 音素级发音评分；

* 复杂情绪识别；

* 用饥饿、生病、哭泣或离开惩罚用户；

* 把宠物包装成真人、心理医生或用户唯一的朋友；

* 首版付费系统；

* 开放式生成对话；

* 运行时机器翻译；

* 依赖生成式大模型自由生成的剧情、记忆总结、纠错与事件分支；

* 把 Web 版本作为正式首发产品。

## 2.1 已确认的产品与技术路线

### 固定内容对话

```text
用户文字 / 语音
        ↓
ASR 转写（可选）
        ↓
用户修改并确认文本
        ↓
预设意图 / 关键词匹配
        ↓
确定性事件分支与固定英文回复
        ↓
人工中文译文 + 预制语音
```

* MVP 不接入生成式大模型；现有 LLM 接口保留，但默认关闭，仅作为未来可选增强；
* 用户可以自由输入，但系统只按明确的预设意图与关键词匹配，不伪装成开放式理解；
* 无可靠匹配时显示中文说明、候选意图和可编辑英文参考句；
* 长期记忆由事件规则或用户显式选择生成，不由模型自由推断；
* 英语反馈由事件目标、表达模式和确定性规则生成；
* 自然复现只使用用户确认过的语言记忆和固定事件配置。

### 正式客户端与 Web 定位

* 微信小程序和 App 是正式产品目标；
* Web 只用于原型、业务流程、内容、接口和自动化测试；
* 正式技术选型优先考虑小程序/App 的录音权限、音频格式、包体、缓存、审核和弱网体验；
* 客户端不得保存 ASR、对象存储或其他服务密钥。

### 语音方案

* ASR：第一候选为千问 `qwen3-asr-flash`，由小程序/App 录音后上传至自有后端，再由后端调用；先用真实中式口音英语样本做单供应商达标验收，准确率、延迟、低置信处理和格式兼容性达标即采用，未达标时再用同一批样本测试豆包 ASR；
* 预制语音：统一使用 **千问 `qwen-audio-3.0-tts-flash`** 在内容制作阶段生成；先用少量定稿台词确定 Morrow 的成人化声音风格，再为每条固定英文台词生成正常语速与慢速版本，人工试听通过后按内容 ID 和文本版本预存；小程序/App 运行时只播放预存文件，不实时调用 TTS；
* ASR 失败时保留文字输入；预存音频缺失、损坏或播放失败时保留英文正文与人工中文译文，事件仍可完成；
* 不接语音服务时，文字学习闭环仍可运行。

### 服务端与存储

```text
微信小程序 / App
        ↓ HTTPS
Serverless 托管容器
  ├─ 鉴权与账号
  ├─ 固定内容与意图规则
  ├─ 事件 / 成长状态机
  ├─ 记忆与共同记忆
  └─ 服务端调用 ASR
        ↓
托管 PostgreSQL + 对象存储 + CDN
```

* 首版优先使用可自动缩容的 Serverless 托管容器，不急于购买长期运行的固定服务器；
* PostgreSQL 保存用户、成长进度、记忆、事件状态、内容版本和文件标识；
* 对象存储保存由千问 `qwen-audio-3.0-tts-flash` 制作并审核通过的预制语音、图片、动画、音效和临时用户录音；
* CDN 只分发预制音频、图片等公开或授权静态素材；用户原始录音不走公共 CDN；
* 用户录音放入私有临时目录，ASR 完成后立即删除或设置 1—24 小时自动过期；
* 数据库只保存确认后的转写文本和文件标识，不保存音频二进制；
* 用户量稳定且容器长期高负载后，再比较固定云服务器成本。

### Morrow 一生成长主线

| 章节 | Morrow 阶段 | 主要英语场景 |
|---|---|---|
| 第一章 | 出生与苏醒 | 问候、自我介绍、感受和简单选择 |
| 第二章 | 童年探索 | 房间、物品、颜色、地点、喜好和简单计划 |
| 第三章 | 第一次上学 | 课堂、同学、规则和请求帮助 |
| 第四章 | 校园成长 | 友谊、合作、冲突、兴趣和目标 |
| 第五章 | 毕业与选择 | 回顾经历、比较方向和表达计划 |
| 第六章 | 初入社会 | 工作、沟通、时间安排和解决问题 |
| 第七章 | 独立生活 | 责任、长期计划、关系和人生回顾 |

成长原则：

* 采用“人生章节 + 关系里程碑”，不按现实年龄逐日机械推进；
* Morrow 成长章节同时规定其可理解词库、主动表达词库、可用句型和台词复杂度上限；Morrow 可以理解略多于自己会说的内容，但不得提前说出后续章节语言；
* 用户英语能力是独立轨道：只调整同一事件的支架和任务要求，不改变 Morrow 的章节、剧情顺序和语言上限；
* 用户选择影响房间、兴趣、活动、职业方向、支线、共同记忆和部分结局细节；
* 单次选择不能永久跳过主要成长阶段；
* 每章由一次性主线事件、可轮换日常事件和记忆回访组成；
* 首批先制作“出生与苏醒”“童年探索”两章，每章 10—15 个事件；
* 同时准备 8—12 个固定对话主题，每个事件至少 2—3 条有效分支；
* 优先扩展不同交互结构，避免只替换文案造成重复。
