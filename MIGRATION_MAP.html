旧 Web 原型 → 固定内容方案 迁移结构图

依据《MIGRATION_PLAN_WEB_TO_FIXED_CONTENT.md》《API_MIGRATION.md》《DATA_MODEL_MIGRATION.md》｜本图为结构示意

一、能力三态盘点（保留 / 修改 / 弃用）

保留

直接复用

  • 事件状态机 / 幂等 / 暂停恢复 memory-event-engine.ts
  • 长期记忆六态与确认流 memory-memory-store.ts
  • 共同记忆册 memory-journal-store.ts
  • 轻量反馈、自然复现 feedback / resurfacing
  • 账号注销与级联删除 account-deletion
  • 异常降级与文字兜底 degradation.ts
修改

按新契约改造

  • 事件内容：启发式 → 规则集 events-v1 → fixed-content-v1
  • 对话主链路：LLM 生成 → 确定性意图匹配 memory-conversation-store
  • UI：双语切换 → 全中文 + 译文按钮 i18n/copy.ts
  • TTS：按需合成 → 单一正常语速预制音频绑定
  • 数据表：+5 新表 +7 新列 schema.ts
弃用

正式端下线

  • MockLLM 流式对话端点 ×4 /v1/conversations/*
  • 按需 TTS 端点 /v1/audio/speech
  • 浏览器录音作为正式端实现 web-recorder-adapter（仅测试）
  • 正式产品英文 UI 整套切换入口

二、主链路替换

现状MockLLM / safeComplete 自由生成回复，事件靠 chooseTransition 启发式推断。
→
新方案读取 fixed-content-v1 规则集 + 确定性意图匹配 + 白名单状态迁移；LLM 适配器保留但默认关闭，不推进状态、不写记忆。

三、边界

Web 仅测试端：React/Vite 工程继续用于内容调试与自动化测试；正式端为微信小程序 + App。
录音适配边界：MediaRecorder 是浏览器测试实现；录音/播放/缓存抽象为客户端适配层，正式端各自实现，服务端只做 HTTPS API。
LLM 策略：adapterRetained=true、enabledByDefault=false、mayAdvanceState=false、mayWriteMemory=false；无密钥也能跑通。
版本与错误：客户端按 schemaVersion/rulesetVersion 校验，不匹配返回中文升级提示，不静默推进。

四、数据模型迁移

现有 23 张表（与 schema.ts / 0000_initial.sql 一致）：19 保留、4 仅加可空列。
→
拟新增 5 表 + 7 列：fixed_rulesets / learning_contents / audio_bindings / user_chapter_progress / intent_resolution_records。
→
5 步迁移：版本字段 → 内容/译文/音频绑定 → 成长世界状态 → 事件实例与意图留痕 → 开关隐私收尾。
硬性规则：所有判定指向真实工程文件；迁移每步可独立验证，无需真实 LLM 密钥；全中文功能 UI，英文学习内容配人工译文；记忆提案仍需用户确认。
