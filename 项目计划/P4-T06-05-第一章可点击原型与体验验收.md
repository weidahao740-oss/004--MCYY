# P4-T06-05 全产品可点击原型与体验验收（第一章样板）

## 1. 状态

🔵 已按确认规则完成本轮原型改造并通过静态检查与浏览器关键流程验证，等待用户体验确认。真实麦克风授权与口语识别效果需由用户在当前设备开口体验后再冻结阈值。

## 2. 任务目标

把全产品共用的关键页面连接成可点击原型，并以第一章真实内容作为首轮样板，验证用户能否在不看说明的情况下完成首次相遇、日常陪伴、情境互动、表达、帮助恢复和互动结束。该原型用于确定整个产品的页面骨架、导航、状态、组件和核心交互，不是只服务第一章的临时原型。

## 3. 必须连通的流程

1. 首次打开 → 中文欢迎 → Morrow 苏醒 → 第一段互动 → 回到陪伴首页。
2. 返回首页 → 动态生活状态 → 触摸／选择／安静陪伴。
3. 陪伴首页 → 与学习内容匹配的生活场景 → 情境理解 → 英文学习内容 → Morrow 行为回应 → 结束层。
4. 跟读节点 → 播放示范 → 用户录音 → ASR／口语识别 → 通过后继续；不能用点击或文字代替完成。
5. 暂未通过 → 重听 → 慢速 → 音节提示 → 回听与再次跟读。
6. 麦克风拒绝、网络失败或环境噪音 → 标记“跟读待完成” → 可离开 → 返回后继续，不错误结算。
7. 暂停／离开 → 返回 → 从最近确认状态恢复。
8. 陪伴首页 → 成长页／词语回声 → 查看当前人生阶段、章节和已经发生的变化 → 返回。
9. 章节完成 → 章节结算；跨人生阶段 → 阶段揭幕短片 → 新阶段首页。

## 4. 验收重点

- 用户能否立即区分中文操作和英文学习内容，不把英文内容卡误认为导航按钮。
- 首页不同状态是否像 Morrow 在生活，而不是轮换任务卡。
- 学习是否发生在与内容一致的生活场景里，而不是在同一背景上连续答题。
- 明确标记为跟读的单词、短语和句子是否必须真实开口并识别通过。
- 口语判定是否以“内容可被理解”为标准，而不是苛求标准口音。
- 多次未通过时的帮助是否温和、有效，并且不伪装成已完成。
- 设备或网络异常时是否允许自然暂停，且保留“跟读待完成”。
- Morrow 的动作、台词、光效和环境变化是否表达同一个意思。
- 章节完成与人生阶段跨越是否被清楚区分。
- 手机窄屏、触控、录音权限和安全区域是否可用。

## 6. 完成标准

- 第一章样板核心流程可以从头到尾走通。
- 不需要讲解也能知道哪些内容是中文操作、哪些内容是英文学习。
- 至少两种动态首页状态都能自然进入互动或陪伴。
- 原型体现四个人生阶段、七个章节的两层结构，并能区分章节结算与阶段跨越。
- 成长页显示当前阶段、当前章节、已发生变化和下一方向，不提前剧透具体未来内容。
- 首两章 4 个基础场景可被事件调用；场景可通过镜头、时间／天气、道具和动作变化复用。
- 所有必修跟读节点只能由真实录音和口语识别通过，不能点击替代。
- 识别失败有逐级帮助；设备或网络异常保留为“跟读待完成”，既不失败也不完成。
- 原型证明通用页面骨架可通过内容、场景、状态、物品和台词变化承载不同事件，不需要为每个事件重做页面。
- 验收通过后冻结全产品通用 UI、视觉、场景接入和核心交互基线；后续章节默认复用，只允许受控扩展。
- 用户确认设计后才进入正式工程。

- 不接真实数据库、正式 API 和真实账号数据。
- 当前不铺开第二章及以后课程内容；但原型范围是全产品通用页面、状态与交互，后续章节必须复用该基线。
- 不修改 `english-pet` 正式工程。
